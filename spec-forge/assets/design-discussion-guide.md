# Focused design discussion

Use this guide to explore consequential architecture or specification decisions with the user. A session is optional unless the user requests it; do not block independent work for an optional discussion.

1. **Prepare first.** Analyze the relevant available evidence and use appropriate specialized skills and tools before asking. Form a reasoned proposal, including trade-offs and meaningful alternatives, without inventing facts or decisions.
2. **Select topics.** Identify up to three high-impact uncertainties, contradictions, boundary choices, or trade-offs grounded in the available evidence. Say why each matters and offer a short discussion; allow the user to change the topics or skip it. Group closely related questions to minimize back-and-forth.
3. **Explore the decision.** Present concise options and a recommended default with rationale when warranted. State what is known, inferred, or uncertain. Ask a single question at a time if a follow-up depends on the answer; otherwise group related questions. Follow the user's answers, challenge contradictions respectfully, and avoid fixed question counts or exhaustive interrogation.
4. **Capture the result.** Summarize agreed decisions, rationale and implications; distinguish them from provisional assumptions and unresolved questions. Link to the supporting sources and record the outcome in the relevant plan or spec when creating or updating that artifact is within scope. Never represent a suggested option or silence as agreement.
5. **Continue.** Use the agreed decisions to update the specification plan, boundaries and checklists as appropriate. If a decision remains open, flag its impact and any work it blocks; continue unrelated work.
